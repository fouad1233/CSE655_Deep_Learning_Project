\textbf{Rules I set for the assistant.} (1) No training run starts without my explicit OK, because every run costs \cotwo{} and counts against the footprint grade. (2) I decide the phases (cleaning rules, split, input size, models, fine-tuning plan); the AI analyses and proposes. (3) Every line of code and every number must be explained so that I can reproduce it by hand in the oral exam. (4) Every training and evaluation run is wrapped in CodeCarbon, and the test set is used once per final model. (5) In notebooks, only new or changed cells are run. (6) The AI logs its own mistakes here.

\section{How I verified AI-generated code and claims}
\begin{itemize}
\item \textbf{Hand calculations vs.\ the code.} Every parameter count, output shape, MAC count and receptive field of my CNN was computed by hand (Table~II of the report) and checked by forward hooks with \texttt{assert}s before training; ResNet18's 11{,}177{,}025 parameters were counted layer by layer and checked with \texttt{named\_parameters()}. This caught case~11.
\item \textbf{Measurements over estimates.} Energy and time come only from CodeCarbon; the AI's estimates were wrong three times (cases 9, 13, 15) and are not used.
\item \textbf{Sanity checks against known values.} The first validation MAE must match the mean baseline (caught case~7, a non-random smoke-test subset); the first-batch loss was recomputed by hand (case~10); validation and test MAE agree within 0.11 years for every model.
\item \textbf{Looking at the data.} Image galleries per score band (greyscale detector, case~2), duplicate galleries, the removed drawing.
\item \textbf{Smoke tests and guards.} Every new piece of code ran on 512 images first; test evaluations and demo cells are guarded so they cannot run twice; the split is checked for determinism (same MD5 on re-run).
\item \textbf{Documentation and papers.} torchvision weight metadata (case~5), the ResNet paper for the 224\,px input, the CodeCarbon documentation for process-mode tracking.
\item \textbf{Reading the outputs myself.} Three cases (2, 17, 19) were found only because I questioned a figure or a sentence. For the report I re-derived the key numbers and checked every figure against \texttt{results/results.csv}.
\item \textbf{References and a rubric check.} All 30 bibliography entries were checked against the publishers' records (Crossref, CVF, PMLR, ACL Anthology, arXiv); three page ranges were corrected. Before submission I had independent AI agents grade the project against the assignment's rubric three times (82, 88, 93/100). Each recomputed the per-layer table, the footprint totals and every derived estimate, and listed gaps and factual slips (e.g.\ an incomplete README, unquantified savings, a wrong statement about MobileNetV3's parameters); I fixed all of them that did not require new training.
\end{itemize}

\section{Reflection}
\textbf{What the tools made faster.} Boilerplate and infrastructure (download with checksum, cached data on the GPU, CodeCarbon wrapper, logging, plotting, \LaTeX) took minutes instead of days, which left time for the decisions that matter. The AI was good at spotting problems in data and logs (conflicting duplicates, a shared GPU in the energy numbers, an underfitting curve) and at turning a vague question (``is the model biased?'') into a concrete, cheap analysis on the validation set.

\textbf{What they made harder.} The AI writes confidently even when it is wrong: an arithmetic slip, a misleading summary of a plot and energy estimates off by $2$--$5\times$ all read like facts. Its explanations often used jargon without definitions, so I had to ask repeatedly until I could follow every step. It also tended to move to the next phase on its own, and to batch several changes, which saves runs but makes effects hard to separate (depth and epochs of the final model).

\textbf{What I would do differently.} Ask for hand calculations and definitions from the start, not after a confusing slide. Write the acceptance checks (asserts, expected baseline values) before running new code. Insist on one change per experiment when the cost allows it. Treat every number from the AI as a hypothesis until a measurement or a hand calculation confirms it.
