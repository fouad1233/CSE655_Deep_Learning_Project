\noindent I used one assistant, running inside the project repository on the work PC (Windows, 2026-11-04/05) and the lab machine (Linux, 2$\times$RTX~5090, 2026-11-18/20). From it I also started separate agents of the same model for two checks: verifying the bibliography with web search, and reviewing the finished project against the assignment's grading table. Durable project context (decisions, progress, this log) lives in the repository (\texttt{.claude/context/progress.md}, \texttt{ai\_usage/ai\_log.md}), so every machine saw the same state.

\textbf{Rules I set for the assistant.} (1) No training run starts without my explicit OK, because every run costs \cotwo{} and counts against the footprint grade. (2) I decide the phases (cleaning rules, split, input size, models, fine-tuning plan); the AI analyses and proposes. (3) Every line of code and every number must be explained so that I can reproduce it by hand in the oral exam. (4) Every training and evaluation run is wrapped in CodeCarbon, and the test set is used once per final model. (5) In notebooks, only new or changed cells are run. (6) The AI logs its own mistakes here.

\section{How I verified AI-generated code and claims}
\begin{itemize}
\item \textbf{Hand calculations vs.\ the code.} Every parameter count, output shape, MAC count and receptive field of my CNN was computed by hand (Table~II of the report) and checked by forward hooks with \texttt{assert}s before training; ResNet18's 11{,}177{,}025 parameters were counted layer by layer and checked with \texttt{named\_parameters()}. This caught case~11.
\item \textbf{Measurements over estimates.} Energy and time come only from CodeCarbon; the AI's estimates were wrong three times (cases 9, 13, 15) and are not used.
\item \textbf{Sanity checks against known values.} The first validation MAE must match the mean baseline (caught case~7, a non-random smoke-test subset); the first-batch loss was recomputed by hand (case~10); validation and test MAE agree within 0.11 years for every model.
\item \textbf{Looking at the data.} Image galleries per score band (greyscale detector, case~2), duplicate galleries, the removed drawing.
\item \textbf{Smoke tests and guards.} Every new piece of code ran on 512 images first; test evaluations and demo cells are guarded so they cannot run twice; the split is checked for determinism (same MD5 on re-run).
\item \textbf{Documentation and papers.} torchvision weight metadata (case~5), the ResNet paper for the 224\,px input, the CodeCarbon documentation for process-mode tracking.
\item \textbf{Reading the outputs myself.} Three cases (2, 17, 19) were found only because I questioned a figure or a sentence. For the report I re-derived the key numbers and checked every figure against \texttt{results/results.csv}.
\item \textbf{References and rubric review.} All 30 bibliography entries were checked against the publishers' records (Crossref, CVF, PMLR, ACL Anthology, arXiv) with a separate agent that used web search; three page ranges were corrected. Before submission, fresh agents reviewed the whole project against the assignment's grading table several times; they recomputed the numbers from the logs and pointed out gaps and factual slips (e.g.\ cases 20--24), which I fixed.
\end{itemize}

\section{Reflection}
\textbf{What the AI made faster.} The parts of the project that are necessary but not the point of the course went very fast: the download with a checksum, the image cache on the GPU, the CodeCarbon wrapper, logging, plots and the \LaTeX{} layout. That gave me time for the decisions that are the point of the course, and I kept those decisions for myself: the cleaning rules, the split, the 200\,px input, head-first fine-tuning, the residual design, and the OK for every training run. The AI was also useful as a second pair of eyes on data and logs: it found the conflicting duplicates, saw that another user's job was running on our GPU, read the training curves of my first CNN as underfitting, and turned my vague question ``is the model biased by age?'' into a cheap analysis on the validation set instead of a new training run.

\textbf{What it made harder.} The AI sounds equally sure when it is right and when it is wrong. A receptive field of 159 instead of 191, ``a quarter of ResNet18's widths'' instead of half, energy estimates two to five times off, a wrong statement about MobileNetV3's parameters and a too-positive summary of my MAE-by-age plot all read like facts. Several of these I found only because I questioned a number, a figure or a sentence myself (the sepia photos counted as colour, the 128\,px input nobody had explained, diagrams that made the networks look linear, the claim that my model was close to ResNet18). Its first explanations also used terms like $k$, $s$, $p$, ``stem'' and ``projection'' without defining them, so I often had to ask again until I could redo each step by hand. Finally, it tends to move to the next step on its own and to combine changes to save runs; the final model changed depth and epochs at once, and I can no longer say which one helped.

\textbf{What I would do differently.} Ask for definitions and hand calculations from the first slide, not after I got lost. Write the checks (asserts on shapes and parameter counts, the expected baseline value) before running new code, because these checks caught mistakes the AI did not. Change one thing per experiment whenever the \cotwo{} allows it. And treat every number the AI gives me as a claim to verify with a measurement or a calculation, because in this project I have to explain every one of them myself.
